## ERROR CLASSIFICATION
**Existing conventions.** `PowerPointFailure` is one enum with the 11 requested categories:
- `PowerPointRenderError` stays the renderer's own detailed error.
- `TaskLensError` stays the app-wide error.
- The new enum sits between them and the user. It holds no path, part name, WebKit code or XML/ZIP detail; those stay in logs.

| Source | Category |
|---|---|
| Import check rejects the stored file as damaged, truncated or another kind of file | `invalidSource` (never rendered) |
| Import check rejects it as unsafe: macro project, path traversal, absolute path, ZIP bomb, too many entries | `securityRejected` (never rendered) |
| Package accepted but its presentation XML is broken (`invalidPresentation`) | `invalidSource` |
| iOS (OfficeImport) refuses the deck | `speakerNotesUnsupported` or `unsupportedPresentation` (see SPEAKER NOTES) |
| A slide, picture, chart or layout missing from the package | `missingResource` |
| Wrong slide count (e.g. 73 of 100), wrong size, failed snapshot, web view failure, no visible slides | `renderingFailed` |
| Slides or metadata can't be written; stored file can't be read | `storageFailure` |
| Fresh cache fails its own validation, or rendered images no longer read | `corruptedCache` |
| Past the time limit | `timeout` |
| Caller left | `cancelled` |
| Anything else | `unknown` |

**Engine phase unchanged.** Every category maps to exactly what the presentation engine showed in A9.3:
- invalid, unsupported, speaker notes and security → `unsupportedSource`;
- the rest → `unreadable`.

So nothing on screen changes until the failure screen (A9.5.2). `PresentationModel.powerPointFailure` carries the category for that screen.

## SPEAKER NOTES
- **Not supported.** Notes are never read, extracted or shown.
- **When the category is named.** iOS reports a refused deck only as an OfficeImport error code, never naming the part it refused. So `speakerNotesUnsupported` is returned only when **both** hold:
  1. OfficeImport's code is 912, the code every deck with notes got in the A8 audit and A9.2 tests (and the same decks without notes rendered); and
  2. the deck's own package contains notes.
- **Otherwise:** any other case is `unsupportedPresentation`, never a guess:
  - 912 without notes;
  - notes with another code;
  - an unknown code;
  - a deck that can't be read to check.
- **On CI:** the real notes deck returned `speakerNotesUnsupported`. The log shows `OfficeImportErrorDomain 912`.

## SECURITY
- The cache re-runs the A9.1 import check on the stored file before every render.
- A rejected file is never handed to WebKit; tests check renders = 0.
- It uses A9.1's own rules: `rejection(of:)` explains the existing check and adds no new one.

## CACHE ERRORS
An invalid cache is still deleted and rendered again (A9.4; all 17 damage tests still pass). If the fresh render fails, its own category is returned. New:
- the fresh cache must pass the same validation before it is used, otherwise `corruptedCache`;
- images that stop reading between validation and display are `corruptedCache`, with no presentation.

## PARTIAL RENDERING
- No partial `PresentationDocument` is ever made:
  - a slide count mismatch (73/100) is `renderingFailed`;
  - the renderer moves images only after every slide;
  - the cache commits only after its metadata is written.
- Tests check `slideCount == 0` and no session on failure.

## TIMEOUT
- **Limit:** the existing 180 s renderer limit, unchanged.
- **Result:** `timeout`, with no cache, staging folder or work folder left behind (test with a 1 ms limit).

## CANCELLATION
New behavior: when the only caller waiting for a render is cancelled (the person leaves), it gets `cancelled` and the render stops.

Tests:
- **50-slide deck cancelled after 0.5 s:** nothing is left, and opening again renders from scratch.
- **Two callers on one render, one leaves:** the leaver gets `cancelled`. The other still gets all 10 slides, and only one render ran.
- **What the person sees for now:** the presentation screen is gone when this happens. Showing nothing alarming in that case belongs to A9.5.2.
