## NEW ISSUES
**N1: PowerPoint slides show pictures from other slides (simulator; device unknown).** Severity: high (a wrong slide in a live presentation). Blocks A9.5 until the device run shows whether it happens there.
- **Reproduction:** open `4-images-shapes.pptx` or `6-large-80-slides.pptx` (a different picture on each slide) on the iOS 26.5 simulator, before `1860f78`.
- **Expected:** each slide shows its own picture.
- **Actual:** from slide 3 on, slides show other slides' pictures. Only 4–12 distinct pictures appear across 80 slides, in a pattern that changes between runs. Slide titles are right. Images: `A9.5.6-simulator/`.
- **Cause:** WebKit's OfficeImport links the slide `<img>` elements to the wrong media. This was seen with no page scripts and with no other conversion running.
- **Ruled out:** media names, picture bytes and size, relationship ids, and concurrent conversions. LibreOffice renders the same files correctly.
- **Age:** not introduced by A9.5; the renderer behaved this way since A9.2, and earlier tests did not check which picture a slide shows.
- **Fix (`1860f78`):** the app can't make WebKit link the right pictures, so it refuses instead of showing wrong slides. The deck reader records the pictures each slide can show (its own, its layout's, master's and theme's). The renderer fails with `renderingFailed(.picturesMixedUp)` if two slides share a picture link but have no picture in common. The user sees the existing failure screen (Try Again, Import PDF). No session and no cache are kept.
- **Tests:** `picturesASlideCanShow`, `picturesOfAnotherSlideAreCaught`, the failure mapping, and the acceptance decks 4 and 6.
- **Limit:** mixed-up shapes, which WebKit draws as PDF images, are not detected.
- **Consequence:** wherever the WebKit problem exists, PowerPoint files with pictures on more than one slide open on the failure screen. The user can use Import PDF instead.
- **Device run:** record whether decks 4 and 6 open with the right pictures or on the failure screen.
