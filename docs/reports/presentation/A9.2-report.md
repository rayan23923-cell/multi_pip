## RENDERING APPROACH
1. A9.1 validation, then `PowerPointDeck` reads the structure.
2. The file is linked into a private temporary folder, and a hidden WKWebView loads it. iOS's built-in OfficeImport converts the deck into HTML, with one `div.slide` per slide.
3. A small injected style:
   - hides the loading placeholders;
   - sets `unicode-bidi: plaintext` on paragraphs (the A8 fix);
   - paints the page behind the slides in a sentinel colour.
4. The renderer waits for the document, fonts and every picture to finish, and for the slide count to stay stable.
5. Each slide is scrolled into view and captured with `takeSnapshot` at 1920 px on the longest side, then written as `slide-001.png` and so on.
6. A capture is accepted only if:
   - no interior area still shows the sentinel colour, which is rechecked with a second colour so that a magenta picture is not mistaken for a gap;
   - for slides with pictures, two captures in a row match.
7. All slides go to a temporary folder first and are moved to the destination only when every slide succeeded.

## WKWEBVIEW
- One at a time: a serial gate is used, and the tests check the peak count is 1.
- Non-persistent data store.
- Page JavaScript is off. Only the renderer's own scripts run.
- No new windows, no link previews, no text interaction, no data detectors.
- Media cannot autoplay, play inline, use PiP or use AirPlay.
- It sits in a hidden window behind the app's own window, with no touch and no VoiceOver.
- It is torn down after success, failure, timeout and cancel.

## OFFLINE
- Nothing is fetched from the network:
  - A content rule list blocks every `http(s)`, `ws(s)` and `ftp` request.
  - The navigation policy allows only the local file, OfficeImport's internal `x-apple-ql-id` scheme and `about:blank`.
- Test `externalPictureIsNeverFetched`: a deck with an external picture made 0 requests, and its picture is simply empty.
- No CDN, remote font, script or server is used.

## SECURITY
- The file is untrusted:
  - A9.1 validation runs first, and its tests include oversized, macro, encrypted and path-escape cases.
  - The structure reader refuses DTDs and entities and caps each part at 16 MB.
  - Relationship targets that leave the package are refused.
- 5 hostile files are refused before WebKit is created, and a corrupt deck is refused too.
- Content process crash → `webViewFailed`.
- Navigation is blocked as described above. Every error removes the work folder.

## SLIDE ORDER
- From `presentation.xml` `sldIdLst` and its relationships. Never from file names, rIds or dates.
- Test: the order deck stores slides in a scrambled order inside the ZIP and renders A–E in exactly the presentation order (checked by colour).

- Read from `sldSz`. When it is missing, the size defaults to 4:3, as PowerPoint does.
- Output examples: 16:9 → 1920×1080, 4:3 → 1920×1440, square → 1920×1920.
- WebKit's slide size is checked against the deck size, within a 2% margin.
