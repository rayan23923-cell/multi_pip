## A9.2 RENDERER FIX (separate commit, A9.2 not amended)
- **Why:** a quick CI run showed the 4:3 test deck rendered as a magnified top-left corner (the A9.2 renderer test `slideSizeFollowsTheDeck` failed).
  - WebKit can change the page zoom after the first layout.
  - The renderer read the zoom before waiting for pictures and took the snapshot after, so a change in between produced a wrong slide image.
  - A9.3 would have shown that wrong image in the presentation.
- **Exact file:** `TLPowerPointRendering/PowerPointRenderer.swift`, `snapshot(...)` only.
- **What changed:**
  - the slide's rect is computed from the current zoom right before every snapshot;
  - a snapshot taken while the zoom changed is retaken.
- **Regression impact:** none seen. All 18 renderer tests pass on the final run, and 100-slide timings are in the same range.
- **Commit:** `3075c48 presentation/A9.2-pptx-renderer: take each slide's rect at the zoom of the snapshot`.

## PPTX → PRESENTATION PIPELINE
1. The Library row or a search result opens `.powerPoint(id)`.
2. This creates `PresentationModel(request: .powerPoint(id))`.
3. `PresentationEngine.load(from: ImagePresentationLoader(powerPoint:…))`.
4. The loader calls `PowerPointSlideCache.slideImages`:
   - If `Generated/<documentID>/Slides/slide-001.png…` already exists, it is reused.
   - Otherwise the A9.2 renderer runs once into that folder. Opening the same file twice at once still renders only once.
5. Each PNG header is checked, and a `PresentationDocument` (source type `powerpoint`) is built with one `.renderedImage` slide per PNG.
6. The existing A5 screen, engine, A6 Auto Play and A7 session take over.
- Nothing bypasses `PresentationEngine`.
- **Storage:** the PNGs stay where the renderer wrote them. They are not copied and not added to the Library.
