## ERROR → UI MAPPING

| Category | Title | Message | Actions |
|---|---|---|---|
| speakerNotesUnsupported | Speaker Notes aren't supported | This PowerPoint contains Speaker Notes that TaskLens can't display directly. Export the presentation as a PDF and import the PDF into TaskLens. | Import PDF, Cancel |
| unsupportedPresentation | PowerPoint can't be displayed | This presentation uses content that TaskLens can't display directly. Export it as a PDF and import the PDF into TaskLens. | Import PDF, Cancel |
| renderingFailed | Couldn't display this presentation | TaskLens couldn't display this PowerPoint presentation. Try again, or export it as a PDF and import the PDF instead. | Try Again, Import PDF, Cancel |
| invalidSource | Invalid PowerPoint file | This file isn't a valid PowerPoint presentation or it couldn't be read. | Try Again, Cancel (no PDF) |
| corruptedCache | Couldn't display this presentation | Same as renderingFailed. The cache is never mentioned. | Try Again, Import PDF, Cancel |
| missingResource | Couldn't display this presentation | Some required presentation content could not be loaded. Try opening it again. | Try Again, Cancel |
| timeout | Presentation took too long | TaskLens couldn't finish preparing this presentation. Try again, or export it as a PDF and import the PDF instead. | Try Again, Import PDF, Cancel |
| cancelled | No screen; returns cleanly | — | — |
| securityRejected | This file can't be opened | TaskLens couldn't safely open this PowerPoint file. | Cancel only |
| storageFailure | Couldn't prepare the presentation | TaskLens couldn't save the presentation data needed to display it. Check available storage and try again. | Try Again, Cancel |
| unknown | Couldn't display this presentation | Same as renderingFailed | Try Again, Import PDF, Cancel |

- The first action is the prominent button, and Cancel is always last.
- Every message is plain language. A test checks that no English or Arabic string on the screen contains a technical word such as 912, WebKit, OfficeImport, XML, ZIP, cache, renderer, macro, path, error, a slash or a format specifier.

## SPEAKER NOTES UI
- The notes title and message appear **only** for `speakerNotesUnsupported`, which A9.5.1 returns only when iOS refuses the deck (code 912) and the deck really has notes. A test checks that no other category mentions notes, in English or Arabic.
- The screen offers Import PDF and Cancel, with no Try Again because retrying can't change the refusal.
- It is verified with a real deck with notes in the UI tests, in English and Arabic.
- Notes are never read or shown.

## GENERIC FAILURE UI
- renderingFailed, corruptedCache and unknown share "Couldn't display this presentation".
- missingResource uses the same title with its own message.
- The UI test opens a real package with no slides, which the real pipeline classifies as renderingFailed, and checks the title, the message, the three actions and the plain language.

## RETRY
- `retry()` clears the failure, resets the engine and calls the same `load()`, so it goes through the same cache, renderer, classification and engine.
- It runs only where Try Again is offered. A test confirms that a retry on a security, notes or unsupported failure is ignored, with no second load.
- Tests:
  - fail, fail with a different category (the screen updates), then succeed: a normal presentation with 4 slides, and each attempt reaches the provider once;
  - the UI test taps Try Again on a real failing deck: the same screen comes back, and the app neither freezes nor loops.

## CANCEL
- Cancel closes the presentation and returns to the previous screen. The UI test goes back to the library and confirms that no error or loading state is left.
- A `cancelled` load shows no failure screen and closes itself.

## IMPORT PDF CALLBACK
- `PresentationModel(onImportPDF:)` is the only entry point. Import PDF runs it only where the button is offered, and a test confirms the callback is not called for invalidSource.
- With no callback, the button is hidden.
- **The app passes an empty callback**, so tapping Import PDF does nothing yet and the screen stays. The PDF fallback is A9.5.3 and was not started.

## SESSION BEHAVIOR
- A failed PowerPoint file saves no session, even after save and leave are called (tested).
- After a successful retry the session is normal: moving to slide 3 saves current slide 2, which is zero-based (tested).

## CACHE BEHAVIOR
- The failure UI never writes the cache. A9.4 still commits slides only after a complete, validated render, so a failed render leaves no cache (covered by the A9.4 and A9.5.1 tests, which still pass).
- Try Again goes through the same cache check, so a damaged cache is rebuilt rather than reused.

## KNOWN ISSUES
- **Auto-play wait limit.** The first CI run failed in three **existing** auto-play tests: the slide never advanced within their 30 s wait.
  - Cause: all of the package's main-actor tests share one thread, and on that runner other suites held it for more than a minute. Even trivial tests reported 75–97 s.
  - The trend was there before this phase: 16 s in A9.4, then 31 s in A9.5.1, which was already at the limit.
  - Fix:
    - The new pure tests now run off the main actor.
    - The two test helpers wait up to 180 s instead of 30 s. The assertions are unchanged: the tests still require auto play to reach the last slide and stop.
  - Result: the suite took 7 s in the green run.
- The 2 known Dynamic Type audit failures on Screen Lens remain, as instructed.

## LIMITATIONS
- Import PDF does nothing in the app until A9.5.3.
- invalidSource offers Try Again as specified, although a damaged file will usually fail the same way again.
- securityRejected offers only Cancel by design, so there is no retry loop.
